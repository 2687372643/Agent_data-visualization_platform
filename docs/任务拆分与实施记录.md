### 1.1 核心配置模块

**状态**: ⏳ 待开始
**路径**: `backend/app/core/config.py`
**依赖**: 无（第一个功能点）

#### 实施方案（实际）

- 使用 `pydantic-settings` v2 的 `BaseSettings` + `SettingsConfigDict`
- 5 组配置分类：App / Database / Redis / LLM / Log，每组分拆为独立 `BaseSettings` 子类
- 子类各自使用 `env_prefix` 隔离命名空间（`DATABASE_*`, `REDIS_*`, `LLM_*`, `LOG_*`）
- 主 `Settings` 聚合子配置，提供 `ensure_dirs()` 方法创建数据目录
- 全局单例 `settings = Settings()`
- 自动计算 `PROJECT_ROOT`（`config.py` 向上 4 级父目录）

#### 变更文件（实际）

| 文件 | 操作 | 说明 |
|------|------|------|
| `backend/app/core/config.py` | 写入 | 5 组配置定义 + 全局单例 + `ensure_dirs()` |
| `.env.example` | 写入（原为空占位） | 完整的环境变量模板，含所有配置项默认值 |

#### 代码逻辑概括

```
Settings (主聚合)
  ├── app_name / debug / version / cors_origins        → 应用基础元信息
  ├── upload_dir / chart_dir / export_dir / temp_dir   → 4 个数据目录路径
  ├── max_upload_size_mb / allowed_extensions           → 文件上传限制
  ├── database: DatabaseConfig                          → DATABASE_URL / pool_size / max_overflow / echo
  ├── redis: RedisConfig                                → REDIS_URL / socket_timeout / cache_ttl
  ├── llm: LLMConfig                                    → LLM_API_KEY / model_name / temperature / max_tokens
  └── log: LogConfig                                    → LOG_LEVEL / format / use_json
```

- `DatabaseConfig/RedisConfig/LLMConfig/LogConfig` 各自独立，可单独实例化
- 所有配置有合理默认值，空 `.env` 也能启动
- `ensure_dirs()` 确保 uploads/charts/exports/temp 目录存在
- 修复：`LogConfig.json` 字段重命名为 `use_json` 避免与 `BaseSettings` 内置属性冲突

```
    │       └── 4.x services (依赖 2.1 + 2.2)
    └── 1.5 redis.py (依赖 1.1)

2.3 utils (无依赖)
    └── 3.x tools (依赖 3.1 base + utils)
        └── 5.x agents (依赖 3.x tools + 5.1 graph)

5.1 graph (依赖 3.x + 5.x agents)
    └── 4.3 task service (依赖 5.1)

6.x frontend (依赖 4.x API)
```

> **实施策略**：优先完成无依赖/少依赖的模块，最大化并行效率。Phase 1(基础设施) 的全模块无依赖关系，可一次性实施。
